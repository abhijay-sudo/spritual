# Source-grounded AI boundary

`src/index.ts` is safe for the Vite client: deterministic local retrieval, citations resolved from supplied records, and a no-model fallback. It sends no network requests. The current three Gita demo records in `packages/content` have unknown redistribution rights and no scholarly review; `aiUseAllowed` is false, so even a configured provider cannot receive them.

`server/` is Node-only. `SpiritualIntelligenceEngine` requires a content loader; `createAiHttpHandler` additionally requires a **real authentication verifier** and exact allowed origins. The demo identity picker is not one. Neither module starts a service or grants public access by itself. The in-process limiter is a narrow abuse guard, not a durable distributed quota. Do not mount this handler publicly before real auth, persistent quota and an internal rights-checked loader exist. The public `fn_knowledge_search` RPC filters redistribution rights, but does **not** establish `may_use_for_ai`; it cannot feed a model by itself.

The optional Groq adapter reads one server environment variable, `GROQ_API_KEY`. No key is present or required for local fallback. Its current fixed endpoint and model come from [Groq's API reference](https://console.groq.com/docs/api-reference) and [free plan limits](https://console.groq.com/docs/rate-limits); availability/quotas must be checked in the account before enabling it. `createChatCompletionsProvider` accepts another server-owned HTTPS endpoint/model/key without changing the engine. Never prefix a provider key with `VITE_` or put it in mobile resources.

The provider path requires `status === 'reviewed'` **and** `aiUseAllowed === true`, plus `consentToSendQuestion === true` for that request. Without that choice, a question receives only the local match or unverified response and is never sent to a model. A future client must explain the external send before offering that choice; an HTTP boolean alone is not evidence that the person saw a consent UI. The engine bounds question/output length, falls back across providers, applies timeouts and a circuit pause, then accepts only structured answers citing retrieved IDs. Citation validation is structural; it cannot certify interpretation accuracy. AI prose is always labelled unreviewed. Private reflection text additionally needs explicit per-use consent before this engine accepts it. No production provider call, conversation persistence, vector search, true token streaming or scholar review has been verified.

Run `node --test tests/aiEngine.test.ts` and `npx tsc --noEmit --module nodenext --moduleResolution nodenext --target es2022 --allowImportingTsExtensions true --types node --strict packages/ai/server/*.ts` from `app/`. Those checks do not prove deployment or real provider behavior.
