## Precise backend blockers and remaining engineering

The existing SQL is groundwork, not the alpha domain persisted on a server. It lacks complete tenant/cohort-scoped invitations, join transaction, completion and delivery operations. `fn_claim_seat` is a comment/stub; catalogue/document publication does not enforce resource-specific paid/free access and current rights expiry. Global access is insufficient. These gaps are **unfinished implementation**, not merely missing credentials.

Before real-backed mode can open: implement transactional tenant-scoped domain operations and authenticated adapter; configure a disposable local Supabase database; apply migrations there; run actual RLS/role, invitation last-seat concurrency, entitlement, withdrawal and revocation tests; verify auth callback/return paths and email capture. Then integrate provider test credentials, durable idempotent events and approved media storage. No secret belongs in a VITE variable. Real content requires documented rights and human review independent of fixture clicks.

`node scripts/test-database.mjs` refuses a missing/remote URL and requires existing migrations 0001–0005, pgTAP and a local test superuser. It does not install tools, apply migrations or silently contact a remote database. Its 20 assertions target existing groundwork, not a complete backend acceptance suite.
