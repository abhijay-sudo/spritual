The [Indian Copyright Act, Chapter V](https://copyright.gov.in/Copyright_Act_1957/chapter_v.html) distinguishes term rules for named literary authors, anonymous works and posthumous works. A publication date alone does not resolve every layer in this edition or a worldwide release. Have a qualified rights reviewer record the exact material, jurisdiction, basis and attribution before changing any `unknown` status.

The reproducible comparison fetches each exact Wikisource page revision and rejects a changed title, revision or raw-wikitext hash. Extraction version 3 removes only line-leading `{{gap}}` indentation and plain `<ref>...</ref>` footnotes before reading a uniquely numbered `<poem>` segment; it excludes a quoted *smriti* line on page 107 that repeats marker 14. Any other markup in the selected segment fails closed. Its ignored report (SHA-256 `459ba15c66f7d75ed27a04fe07d0243d1b99b6ace2d3c1ea72df8caedb8c80d9`) records both candidate and page-transcription text so an editor can inspect every difference. These are **two online transcriptions**, not an independently edited transcript of the scan.

An unreviewed spot-check downloaded the [Commons 523-page file](https://commons.wikimedia.org/wiki/File:%E0%A4%B6%E0%A5%8D%E0%A4%B0%E0%A5%80%E0%A4%AE%E0%A4%A6%E0%A5%8D%E0%A4%AD%E0%A4%97%E0%A4%B5%E0%A4%A6%E0%A5%8D%E0%A4%97%E0%A5%80%E0%A4%A4%E0%A4%BE.pdf) (local SHA-256 `9e4a431292647abf1b619dca5bbc5e1f6ecd39eda578776a8f5348376ff21098`) and rendered PDF pages 86, 87, 90, 95 and 103. The image sequence jumps from printed **81** on PDF page 86 to printed **84** on PDF page 87, explaining why 2.54–2.56 cannot be recovered from this scan. [Page 90's transcription](https://sa.wikisource.org/w/index.php?oldid=366528) labels the bottom verse **12**, while its image visibly labels it **62**; the strict comparator does not silently correct the transcription, so 2.62 stays pending. [Page 95](https://sa.wikisource.org/w/index.php?oldid=366522) visibly has 2.70, now compared: the candidate reads `यद्वत्` where the page transcription reads `यत्`, among other layout differences. [Page 103](https://sa.wikisource.org/w/index.php?oldid=366464) visibly has 3.6, but its page transcription leaves that verse outside a `<poem>` block; it stays pending under the strict extraction rule. This spot-check diagnoses gaps; it is **not** signed Sanskrit image proofreading, a resolution of any variant, or permission to release.

## Recommended first release path

The least ambiguous route to investigate is an **independent, verse-only transcription from the 1901 scan**, with one exact file hash and page citation per verse. Record the print edition, scan provenance and territorial rights analysis separately from the Wikisource comparison. Do not copy its commentaries or modern translations. Author the English/Hindi explanations and Roman guide separately; review those exact revisions as well.

Start editorial work with **Gita 2.47**, because the two page transcriptions agree after limited normalization and the app already has a demo journey for this reference. The agreement only makes it an efficient *review candidate*, not publishable text. Add 2.49–2.51 to the pilot only after image proofing; keep 2.48 and every other mismatch out of any release candidate until a Sanskrit editor resolves the actual scan reading. Do not expand this to 700 verses by passing a structural validator.

For each proposed released rendering, require all of the following evidence:

1. Immutable source file/page identifier and hash; actual scan-image comparison signed by a named Sanskrit reviewer, including every correction and verse-number decision.
2. An edition-specific rights record: exact works used, public-domain or permission basis by launch territory, reproduction/adaptation/commercial distribution scope, attribution text and source URL. Treat AI/model use as a **separate** permission decision; leave `may_use_for_ai=false` unless independently cleared.
3. Exact-version approval of Sanskrit, transliteration, English and Hindi renderings and any story/interpretation by named qualified reviewers. Record reviewer identity/date, revision hash, source citations, and a way to withdraw a disputed version.
4. Only then update the content metadata and use the existing `knowledge_sources` / `knowledge_editions` / `knowledge_source_licenses` / `knowledge_renderings` gates in [migration 0006](../supabase/migrations/0006_knowledge_corpus.sql); execute the public-content preflight and an authenticated delivery test. These schema files have **not** been applied to a production project. Passing a local metadata predicate alone is not authorization to publish.

Until that record exists, the current `npm run content:release-preflight` should keep blocking publication. No candidate verse, translation, image, narration or AI context is cleared by this research note.
